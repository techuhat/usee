# Testing strategy

## Test pyramid

| Level               | Focus                                         | Examples                                                                                          | Environment                                         |
| ------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| Unit                | Pure behavior, fast and deterministic         | timing/keyframe interpolation, project migration, blur geometry, error mapping, contract schemas  | Node/Vitest                                         |
| Property/regression | Invariants and known edge cases               | timeline arithmetic, coordinate mapping, generated-camera constraints                             | Node/Vitest with seeded fixtures                    |
| Integration         | Adapter contracts and real process boundaries | project atomic save/open, FFmpeg manifest runner, IPC handler validation, host protocol handshake | Dedicated fixture environment                       |
| Native hardware     | Windows API behavior                          | WGC source/resize/device loss, WASAPI device changes, encoder fallback                            | Windows self-hosted runner/lab hardware             |
| End-to-end          | User-critical flows                           | open app, start/stop recording, project creation, preview, export                                 | Packaged/signed-like desktop build                  |
| Visual/golden       | Render-plan consistency                       | cursor, camera, blur, effects at named frame times                                                | Versioned media fixtures and image/video tolerances |
| Performance/soak    | Responsiveness, memory, recovery              | 1080p/60 and 4K sessions, multi-monitor, long export, forced host crash                           | Controlled benchmark machines                       |

## Isolation rules

- Domain/application tests use fakes that implement ports. They do not mock internal pure functions.
- Native/FFmpeg tests use small, sanitized, deterministic media fixtures; never personal recordings.
- Tests never call a real capture device in ordinary CI. Hardware tests are separately labeled and opt in.
- Contract tests run against every renderer/preload/main/host protocol change and include incompatibility fixtures.
- E2E automation must drive the public UI/capability surface, not private implementation globals.

## Required gates

Every pull request runs formatting, lint, import/dependency boundary checks, TypeScript typecheck, unit tests, and a production renderer/main build. Main-branch or release workflows also run package smoke tests. Native integration, export, visual, and performance suites run on appropriate Windows runners before a release candidate is approved.

`npm run check` runs every pull-request gate locally in the same order as CI (`.github/workflows/ci.yml`). CI first builds the native recorder host and runs its tests, so the host's integration tests and the E2E suite, which skip without it, run against it; after the gates it runs the E2E suite against the built app. GitHub's Windows runners have no GPU: Direct3D runs there on a software adapter without a video processor, so the host's test of GPU scaling skips. The E2E helper sets the page to 1328 x 786, the size the preview goldens were made at, since the window's frame takes more or less of the 1360 x 900 window with the display's scaling; the runner's screen starts at 1024 x 768, too small for that, so CI sets it to 1920 x 1080 first. The export specs skip there, as CI builds no FFmpeg runtime. Reading a run's log takes a GitHub sign-in, so a failed run also posts the last 40 lines of its log as an annotation, which anyone can read.

## Where tests live

| Kind                    | Location                             | Runner                          |
| ----------------------- | ------------------------------------ | ------------------------------- |
| Unit (owned behaviour)  | Next to the code, `src/**/*.test.ts` | `npm test` (Vitest)             |
| Cross-package and tools | `tests/integration/**/*.test.ts`     | `npm test` (Vitest)             |
| Electron end-to-end     | `tests/e2e/**/*.spec.ts`             | `npm run test:e2e` (Playwright) |
| Native unit             | `native/recorder-host/tests/`        | `npm run build:native` (CTest)  |

Vitest resolves `@usee/*` to package sources, so unit tests never need a build. E2E tests launch the built app and use only the page and `window.desktop`.

Tests that need the native host (`tests/integration/recorder-host.test.ts`, `recording-pipeline.test.ts`, and the E2E specs that record) skip themselves until it is built. They record the host's synthetic test pattern, test tone and pointer (`synthetic-0`, `synthetic-audio`, and the synthetic pointer that comes with the synthetic display), the pattern as a window (`window-synthetic`, 960 x 600; the host lists it first, beside the machine's real windows, which no test records) and regions of the synthetic display, chosen in E2E by dragging on the area picker, a window that shows the screen through but records nothing, and the E2E helper points all app data at a temporary directory, so no test touches the real screen, microphone or user profile. The synthetic sources run on the session clock: the pattern (a checkerboard with a box that moves a step every 250 ms) and the pointer (a 4-second circle with a click each second) are the same at the same moment of every recording, so recorded frames can be compared.

## Visual goldens

`tests/e2e/preview.spec.ts` records the synthetic sources, steps the playhead with the arrow keys to named frames, and compares the preview canvas with the PNGs in `tests/e2e/preview.spec.ts-snapshots/`: first the camera generated from the synthetic clicks, where it holds on the second and on the third click (between pans, so a recording that starts a little later shows the same picture); then, with auto zoom off, the same click as a pulse, a ring and a bounce; then, with a zoom and a moving blur added through `window.desktop`, the cursor, a click ripple, zooming in, a click and the hand cursor under the zoom, and the same zoom turned in 3D, floating as a card over a light canvas with rounded corners and a shadow (a light canvas, since the per-pixel tolerance cannot tell a dark background from the dark pattern). Each moment is in the middle of a pattern step and on the 60 fps frame grid, and the spec waits for the canvas's `data-source-us` and `data-frame-us`, so the picture is exact on one machine; the 1 % pixel tolerance absorbs encoder and GPU differences between machines. The app runs at device scale 1 in E2E, so screenshots have the same size on any display; the picture's size follows the window's (1360 x 900 by default), so a smaller screen that shrinks the window changes it. An app that exits during a test prints its exit code and the end of its stderr. After an intended visual change, regenerate with `npx playwright test --config tests/e2e/playwright.config.ts preview --update-snapshots`, look at every image, and commit them with the change. The goldens carry a `-win32` suffix: other platforms have none yet.

## Initial foundation coverage

The foundation covers the contracts (IDs, time units, `AppError`, `Result`, the IPC registry), the main-process security helpers (dev-server origin parsing, `app://` path confinement, CSP, trusted origins), the IPC router and preload bridge, and the boundary checker itself. The E2E suite proves the shell boots from `app://`, exposes only `window.desktop`, enforces the CSP, and refuses remote navigation and new windows. Future feature work must add tests at the layer where the behavior is owned.

Phase 2 added the editor's layers: the timeline commands (including a seeded property test over random edit sequences), the project session's history and background saves, the repository's migrations and atomic saves, the media server's range parsing and URL confinement, and the renderer's project store and timeline math. `tests/e2e/editor.spec.ts` records the synthetic sources, then splits, deletes, undoes and redoes in the UI, checks the saved manifest and a reopen, and zooms the timeline (buttons, Ctrl and the wheel, following the playhead, Fit).

Phase 3 added the effect evaluators with property tests (the camera never leaves the frame or jumps between moments 10 ms apart, the smoothed cursor never leaves the raw path's range), frame composition at named moments (`composeFrame`), the compositor's drawing math against a recording 2D context, the editing rules for effects (new effects, timeline drags, zoom and blur keyframes), the pointer stream from host to editor, and the visual goldens above. `tests/e2e/effects.spec.ts` adds, aims, scales, moves and keyframes zooms and blurs in the UI, checks with the canvas's pixels that a blur shows where it was moved, sets the cursor with undo and redo, and reads the saved manifest.

Phase 7's export worker also runs against a real FFmpeg build in `tests/integration/ffmpeg-export.test.ts`, the one `USEE_FFMPEG_EXE` names or the `npm run build:ffmpeg` output (none is checked in, so it is skipped without either): the build must list every component the worker's commands use (muxers, demuxers, encoders and decoders), one second of raw RGBA frames must export to an MP4 (`ftyp` `isom`) whose published size and hash match, and validation must fail on a truncated MP4. The unit tests' fake runner cannot catch a build that lacks a muxer; this test refused the first 9.0.2 candidate for exactly that. `tests/integration/ffmpeg-build-config.test.ts` keeps `scripts/ffmpeg-build-config.mjs` in step: its flags equal ADR-008's configure command, enable every component the capability probe requires and nothing GPL, nonfree or networked, and its runtime manifest passes the app's schema. `tests/e2e/export.spec.ts` exports through the Export panel in the unpackaged app with that build, answering the native save dialog in the main process, checks the MP4 with the same FFmpeg, records how long the export took, and cancels a second export; it is skipped until the build exists.

Annotations (2026-11-17) added domain tests that they fade in and out, are listed in the clip's order and are refused out of bounds; compositor tests that text lands where it was put, sized with the zoom and on its label, that an arrow ends on its point and a box sits on its bounds, faded as they fade, and that the cursor stays on top; and `tests/e2e/annotations.spec.ts`, which adds words with T, types them, colours them, moves them by their frame, turns them into an arrow and drags its point, then a box, checks the preview draws the box's green and stops when it is turned off, and reads it back from the saved manifest.

`tests/e2e/recording-controls.spec.ts` (2026-11-09) starts a recording with the window allowed to minimize and checks, in main, that it does and that the stop shortcut is held, then stops through the bridge (a test cannot press a global shortcut) and checks the window is back, the shortcut released and the editor open; a second test checks the countdown, that Escape stops it before anything records, and that a recording starts only once it ends. Every other spec launches with `USEE_KEEP_WINDOW_WHILE_RECORDING=1`, honoured only unpackaged, since Playwright cannot click in a minimized window.

`tests/e2e/export-recovery.spec.ts` (2026-11-09) kills the app's main process (found with `process.pid` inside the app: Playwright's own child is a launcher) while an export renders, starts the app again on the same data directory (`launchDesktopApp({ dataDirectory })`), and checks the job is reported failed with `export.interrupted` and the destination has no file. `tests/e2e/soak.spec.ts` runs only with `USEE_SOAK=1`: it exports a 30-second recording at 1080p30 and 4K30, decodes each in full, checks its size and length, and records the time and the app's peak memory as annotations.

`tests/e2e/export-color.spec.ts` (2026-11-09) exports a recording without zoom and compares, as the editor plays both back, the colour of a tile, the background and the synthetic yellow box in the recording and the export, each channel within 3 levels: a BT.601 conversion moved the yellow by 5-7.

Picture focus (2026-11-08) added tests that picture changes become focus candidates once per place while it keeps changing, below a click, leaving out a change over much of the frame; that the reader averages each cell's luma, finds a dialog's box, reads typing a character at a time as a line, and ignores a blinking caret and, after it starts, a playing video; and that the picture strategy names the picture changes in its run's input and looks where they are. `tests/e2e/picture-focus.spec.ts` turns "Follow changes on screen" on for a synthetic recording, waits for the editor to read its picture, checks the derived file holds the box's changes in the box's band and the saved run names `pointer-picture-focus`, and turns it off again.

Ordered decoding for export (2026-11-08) added tests that the MP4 index lists a recording's samples (offsets through chunks, presentation times with composition offsets, keyframes, 64-bit offsets, signed offsets), takes only an identity edit list and refuses fragments, other codecs, compact sizes and broken tables; that it finds the `moov` a recording writes last by reading box headers only; that it picks the frame a video element shows at a time, in presentation order; and, with a stand-in `VideoDecoder`, that the decoder decodes each frame once in time order, repeats a frame without decoding, starts over at a keyframe to go back or skip ahead, reaches the last frame by flushing, fails when decoding fails, and reads media in windowed byte ranges, never a whole file.

The filmstrip (2026-11-16) added tests that it reads every keyframe or an even share of a long recording's, lays tiles on the clip's grid so they stay put as the timeline scrolls, starts a trimmed clip at its source, and that the ordered decoder lists its keyframes; `tests/e2e/editor.spec.ts` checks the recording's clip draws its filmstrip.

Thumbnails (2026-11-09) added a repository test that a project's thumbnail is kept, listed inline as a data URL and refused when it is not a small JPEG or the bundle is outside the projects folder; `tests/e2e/editor.spec.ts` checks the recording shows in Home's list by its thumbnail.

The app shell (2026-11-08) added tests that the settings schema refuses another version, unknown fields such as a remembered microphone, a default canvas that names an image, and values out of range; that the settings manager starts from the defaults, saves a change and reads it back, keeps every change when several arrive together, falls back to the defaults with a warning for a damaged or foreign file and refuses a change that would make the settings invalid; that the renderer's settings store shows a change at once and restores the saved settings after a failure; and that a new recording's project starts with the looks it is given. `tests/e2e/settings.spec.ts` changes the settings on the Settings page and reads them from `settings.json`, records a recording that starts with them, adds a 3D zoom from the 3D camera tab and from the toolbar and undoes one, opens the export panel on the remembered quality, and finds the recording on the Recordings page.

Phase 4 added the click focus strategy and the camera planner with a fixture regression test and a seeded property test (zooms are valid, ordered and never overlap; the camera is fully in at every click once it has had its lead), the generated layer under the clip's own zooms, the analysis runs and when they are stale (input hash, strategy version), the override commands, the save that a change made just as a save finishes still gets, the renderer's auto-zoom bars, and the camera transform: a flat view is the plain crop, a turned one turns the way its rotation says, and over random poses and shapes it keeps the picture filling the output and maps back exactly. `tests/e2e/auto-zoom.spec.ts` checks that a recording's clicks give a generated zoom on the timeline, turns it off and back on, takes it over as the clip's own zoom and undoes that, turns the layer off, and reads the run's provenance and the overrides in the saved manifest; `tests/e2e/effects.spec.ts` also tilts a zoom with its slider and chooses how clicks show. Phase 5 added the picture's layout on the canvas, the canvas painting and the rect it draws into, the canvas style's validation and its migrations, clip speed through every timeline edit (the seeded property test mixes speed changes into its random edits), timeline math at a speed, the cursor's colour and spotlight, and the camera's motion and its blur. `tests/e2e/canvas.spec.ts` styles the canvas from its panel, with motion blur and a spotlight, and reads the saved manifest; `tests/e2e/speed.spec.ts` plays a clip at 2×, undoes and redoes it, and reads the saved manifest. Phase 6 added the card transform (a flat card at its place, a pulled-out one shrunk about its centre, a turned one showing the canvas past its edges, a wider lens looking deeper, and over random views it maps back exactly), the card's outline and the detail a turned card is composed at, the shadow under any shape, manifest version 9 and its migration, smooth paths through keyframes (through every keyframe exactly, still moving through one that flows, at rest at one that holds, never past a keyframe), the turn as camera motion, the lens easing in, the presets, holding a keyframe and turning by a drag, the generated camera's turn toward each action, and focus where the pointer rests. `tests/e2e/motion3d.spec.ts` drives all of it through the UI and checks three goldens on a light canvas; its `goTo` steps from where the preview has settled, since a press on the timeline seeks and the preview catches up later. The turned-zoom golden in `tests/e2e/preview.spec.ts` moved to a light canvas too: the per-pixel tolerance cannot tell the dark default background from the dark pattern. The review follow-ups added tests that the drawn cursor keeps up with a steady pointer, moves on through a click at the pointer's own pace, and lands exactly on a click just after a quick move without moving back by as much as a pixel; that each click effect draws its own way; that version 4 projects' clicks migrate; and that an earlier build's folders move to the new name once.
