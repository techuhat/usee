# Module boundaries

All modules expose typed inputs/outputs, own their state explicitly, return typed `Result`/`AppError` values across boundaries, and publish rate-limited typed events. Their interfaces belong in `packages/application`; implementations belong in adapters or the native host.

## Auto-zoom plug-in seam

```text
Immutable interaction/media inputs
  → FocusStrategy.analyze(context, cancellation)
  → FocusCandidate[]
  → CameraPlanner.plan(candidates, constraints)
  → GeneratedCameraTrack (provenance included)
  → resolved camera track = generated layer + manual overrides
```

`ClickBasedFocusStrategy`, `WindowBasedFocusStrategy`, `AIContentFocusStrategy`, and `ManualFocusStrategy` return compatible candidates or tracks. The editor consumes the resolved camera track only; it never branches on the algorithm that produced it.

Phase 4 implements the click-based strategy (`clickFocusStrategy` in `packages/application/src/camera-analysis.ts`, over `clickFocusCandidates` and `planCameraTrack` in `packages/domain/src/focus.ts`). Phase 6 makes `pointerFocusStrategy` the default: clicks and the places the pointer rests (`restFocusCandidates`). Rest detection sorts clicks once, then advances through the click windows and pointer rests in one pass; its scan is O(M + C) after sorting, for M pointer moves and C clicks. Project-open analysis runs after each pointer stream is read (`staleCameraRuns` skips a current run); keep this work measured and move heavier strategies behind the `FocusStrategy` interface into a cancellable worker. The resolved camera is the generated layer with the clip's own zooms over it (`cameraViewAt` with a base view). The generated layer follows the pointer as each frame is composed (`followPointer` in `packages/domain/src/camera-follow.ts`, ADR-010): it moves just enough to keep the pointer, averaged as far ahead as behind, inside the middle of its view, turning in 3D toward where it looks; the clip's own zooms are never moved.

## 3D camera seam

`CameraPose` contains normalized anchor/position, scale, stable rotation representation, projection/perspective, and easing/interpolation metadata. `ZoomKeyframe` is a constrained camera pose, not a second competing transform system. Rendering evaluates a pose per frame and compiles it to a transform, allowing pan, zoom, tilt, rotation, perspective shift, and focus transitions without hard-coding effects into UI controls.

Phase 4 implements it. `CameraPose` (`packages/domain/src/camera.ts`) is the point looked at (`anchor`), how close (`scale`) and an optional `rotation`: Euler angles in one fixed order, at most 30° each, so they interpolate one by one without gimbal lock. A zoom's keyframes are camera poses, each with its easing. `cameraViewAt` evaluates the pose for a frame and `cardTransform` compiles it into the projective transform of a card over the canvas (Phase 6); the lens is a view's field of view, 30° unless it says otherwise.

## Blur seam

`BlurEffect` has a target/range, parameters, and a `MaskTrack` of rectangle, ellipse, or polygon geometry. `TrackingBinding` is optional. A future object tracker writes the same mask track, so neither the timeline nor editor model changes when tracking arrives.
