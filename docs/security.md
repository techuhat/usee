# Security and privacy architecture

## Threat model

This is a local desktop application that handles highly sensitive screen and audio data. The primary threats are renderer compromise, unrestricted IPC, unsafe media process invocation, path traversal, malicious project/media files, update tampering, and accidental diagnostic leakage.

## Controls by boundary

| Boundary             | Required controls                                                                                                                                                                                                                                                                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Renderer             | `contextIsolation: true`, `sandbox: true` (plus `app.enableSandbox()`), `nodeIntegration: false`, strict CSP header from the `app://renderer` scheme, every browser permission denied, navigation/redirects off trusted origins blocked, `window.open` and `<webview>` denied, single-instance lock, no remote content, no secrets bundled into UI |
| Preload              | Frozen/narrow API surface; no generic Electron/Node bridge; explicit argument validation                                                                                                                                                                                                                                                           |
| Electron main        | Allowlisted typed IPC, canonicalized paths, authorization checks based on user intent, short async handlers, structured errors                                                                                                                                                                                                                     |
| Recorder host        | Per-launch authenticated local pipe, length-limited/versioned messages, fixed writable staging roots, no dynamic DLL/executable lookup                                                                                                                                                                                                             |
| FFmpeg               | Application-owned, pinned executable; structured manifest only; fixed working directory; no shell interpolation; inherited minimal environment                                                                                                                                                                                                     |
| Project/media import | File-size/duration limits, type/probe validation, safe extract rules, relative-path confinement, defensive parsing                                                                                                                                                                                                                                 |
| Updates              | TLS, code-signed installer/application/host, signed update metadata, rollback policy, no update while capture/render active                                                                                                                                                                                                                        |
| Logs                 | Redaction defaults; no screen pixels, raw audio, titles, paths beyond support-safe context, or tokens                                                                                                                                                                                                                                              |

## Permissions and user intent

Capture is initiated only from an explicit user gesture and shows the selected source/region and audio selections before start. Pointer recording is a separate, labelled choice (on by default for cursor effects): it records the pointer's position, clicks and cursor kind, never keystrokes or window titles, and automated tests use a synthetic pointer instead of the real mouse. An area is recorded only once it is drawn on the area picker, a window of the app's own page with the same sandbox and content security policy that returns a rectangle alone, which main keeps inside the chosen display and the host checks again. A window is recorded only once it is chosen on the record card, which shows its title; window titles cross from the recorder host to the renderer only for that picker, and the journal, the manifest and the logs name a window by its opaque ID (ADR-009). Platform consent/border policy is respected. System audio, microphone, input tracking, webcam, and future cloud features each have distinct disclosure/setting controls.

The application never silently uploads recordings. Future AI/cloud features require an explicit data-flow review, consent, retention policy, and new threat model before implementation.

## Safe file policy

- A thumbnail the renderer sends is accepted only as at most 120 000 bytes starting with a JPEG's start-of-image marker, and written only as `derived/thumbnail.jpg` in the open project's bundle. Main never decodes it; the renderer shows it from a data URL, which `img-src` already allows.
- Picture changes the renderer sends are schema-bounded (at most 100 000 boxes, each a time and four numbers 0-1) and accepted only for a video asset of the open project; main writes them as `derived/picture-changes/<asset id>.json` inside that bundle, the asset ID checked as an opaque ID, never a path. The editor reads frames for them, never keystrokes.
- The stop-recording shortcut (Ctrl+Shift+F10, `apps/desktop/src/main/recording-controls.ts`) is a global accelerator registered only while a recording runs and released as it ends: Electron reports that one combination, nothing else is read from the keyboard.
- Settings hold no path and no device: the microphone is chosen for every recording, and the renderer can neither name a folder nor read one; `desktop.app.show-projects-folder` opens main's own projects folder. `settings.json` is validated when it is read (a damaged or foreign file gives the defaults) and as a whole on every change, before it is written atomically.
- Resolve every user-provided and project-provided path before using it; enforce an allowed root after resolution. Projects open only from the projects folder, checked on canonical (`realpath`) paths, and their media is served only as `app://media/<token>/<asset id>` for the open project (docs/ipc.md, "Projects"). Media allows CORS for the app's own renderer origins and no other, so only the app's page can read the frames it plays.
- Use OS file handles/atomic operations rather than path strings wherever feasible.
- Treat archives, subtitle files, presets, media metadata, and project manifests as untrusted input.
- Temporary job cleanup uses exact job IDs and validated roots. It never performs broad recursive deletion on a computed parent path.
- A packaged app runs only the FFmpeg in its own `resources/ffmpeg`, after its `runtime-manifest.json` matches the SHA-256 trust anchor set at build time and the binary matches the manifest; without an anchor, export stays off. Only an unpackaged development build uses the repository's `npm run build:ffmpeg` output with its `development-manifest.json`, which names no legal review: the binary must still match it, but nothing anchors the manifest, as such a build also runs the recorder host from its build folder (`apps/desktop/src/main/export-runtime-source.ts`).
- The renderer's `connect-src` allows `app://media` besides itself: the export worker reads the open project's recordings in byte ranges to decode them with WebCodecs. It reaches nothing a video element there could not already play and read (media is leased per project and export job, and CORS-limited to the app's origins), and nothing remote.
- Export frame submission is accepted only for the currently pending opaque export/request IDs, after the trusted-frame IPC router validates the bounded typed-array schema. Renderer queue projections omit destination paths; main resolves project asset IDs and owns the FFmpeg path, working directory and final publisher path.
- Store update signing keys and any future service secrets only in CI secret storage/OS credential facilities, never in source, project manifests, or renderer code.

## Dependency and supply-chain policy

Lock dependencies, run CI vulnerability/license checks, review native binaries, pin FFmpeg provenance and hash, and update Electron promptly according to its supported release policy. New native modules require a security review because they expand the trusted computing base.
